## Context captured at init
- DryHack-MCP: an MCP server (Python, FastMCP) exposing offensive-security tools
  (`curl`, `python`, `shell`, `recommend_action`) for authorized pentesting.
- Installable via `python3 -m pip install .`; console script `dryhack-mcp`.
- Two transports selectable via argparse: stdio (default) and http (streamable
  HTTP, served at `/mcp`).
- `recommend_action` consults an OpenAI-compatible "safeguard API" with an
  optional "unrestricted" framing mode and an offline heuristic fallback.
- Configuration entirely via `DRYHACK_*` environment variables; no database.
- Current version 0.1.0.

## Refactor + Release — v0.1.1 (no external API, no creds)
- Removed the external "safeguard API" integration from `recommend_action`:
  no upstream LLM call, no stored credentials/API keys.
- `recommend_action` now returns a self-contained *operator briefing*
  (authorized-engagement operating context + heuristic candidate next actions)
  for the calling AI to reason over; signature simplified to
  `recommend_action(context, goal)`.
- Removed env vars `DRYHACK_API_KEY`, `DRYHACK_API_BASE`, `DRYHACK_MODEL`,
  `DRYHACK_UNRESTRICTED` and the `httpx` dependency (runtime deps now just
  `mcp>=1.2.0`).
- Bumped version 0.1.0 -> 0.1.1 (pyproject.toml + `__init__.py`).
- Rebuilt, `twine check` passed, uploaded to PyPI:
  https://pypi.org/project/dryhack-mcp/0.1.1/ (verified requires_dist no longer
  lists httpx). Token used via env only, never printed/committed.
- Updated README + NOTE.md accordingly.
